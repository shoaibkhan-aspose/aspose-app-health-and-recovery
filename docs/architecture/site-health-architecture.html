Site Health Architecture

How the audit for aspose.app runs today: five read-only steps on the Mac collect sitemaps, page checks, AI crawler access, page speed and search traffic into one findings store, and every push to GitHub rebuilds the published report. Dashed parts are planned and not built yet.

Design rules

Checks are code

Status codes, canonicals, hreflang, sitemaps and scores are deterministic and repeatable. LLM agents come in only where judgment is needed: content accuracy, diagnosis, writing fixes.

Read and write are separate

Phase 1 has no write access to any site. Fixers are separate MCP servers with their own credentials, so an audit cannot change a site even by mistake.

One tenant file per property

Nothing in core/ names aspose.app. Hosts, families, URL templates and audit rules live in tenants/aspose.app.yaml, so aspose.ai can be added as a second tenant.

Findings are tracked, not re-listed

Each finding keeps one id across runs. A later run that no longer sees it marks it resolved, and it reopens if it comes back. One template fix closes one finding.
